# External-tool ingestion — contract, per-tool instructions, ground-truth fold, precedence

   **Read-only tool contract (enforced for EVERY tool in this step).** A tool may ONLY read source and write its OWN report artifact — analysis JSON to the scratchpad, or a coverage report to the repo's conventional `coverage/` dir. NO tool may modify source files: never pass `knip --fix`, `biome --write`/`--fix`, a dependency-cruiser auto-fix, or invoke any ts-morph mutation / `.save()`. The `metrics.mjs` / `tool-probe.mjs` / `coverage.mjs` / `semantic.mjs` helpers are **stdout-only** by construction. The single code-EXECUTING action permitted is running the test suite to produce a coverage report (writes the report, never source) — and only through the coverage checkpoint. A tool that cannot run read-only is treated as `absent`.

   - **Run the present ones** (status `configured`/`installed`) to the scratchpad and parse them:
     - dependency-cruiser (sharpens **L**): **scan from the repo ROOT, then filter to the target** — `npx depcruise . --config <config> --output-type json --metrics`, then keep modules whose `source` and violations whose `from` start with `<target>`. **Always exclude build/report/sandbox output from the root scan** — add `--exclude '(^|/)(dist|build|out|coverage|reports|\.stryker-tmp)/'` (plus any repo-specific output dir) to EVERY depcruise invocation in this step: an unexcluded root scan sweeps compiled mirrors and mutation sandboxes into the graph (verified: 1,853 modules with every "violation" sandbox noise, and the likec4-conformance fold's `unmapped_files` inflated by hundreds of dist copies), which poisons Ca/Ce/I, the orphan signal, and the conformance mapping at once. **Do NOT scan the target subpath directly** (`depcruise <target>`) when the target is not the repo root: a scoped scan cannot see `app/`→`lib/` (cross-boundary) imports, so afferent `Ca` is undercounted AND the `no-orphans` rule FALSE-flags every target file consumed only from outside the target (verified: a `lib`-scoped scan reports `lib/account/display.ts` as an orphan though 9 app pages import it; a root scan correctly shows `afferent=9`, 0 orphans). Capture the FULL graph (modules + edges + `circular`/orphans) **and** the per-folder stability metrics (afferent `Ca` / efferent `Ce` / instability `I = Ce/(Ca+Ce)`), not just `summary.violations`. Count `forbidden`/`required` rules in the config: **if few/none, "no violations" is NOT meaningful** — note it and SUGGEST `depcruise --init` / boundary rules; the graph + metrics are still ingested. **Dead-wood (reachability, sharpens A):** harvest any `reachable`/`no-orphans` rule the config already defines, AND — since the ROOT scan yields afferent coupling — treat modules with `Ca=0` that are not entry points (framework entrypoints, `*.d.ts`, tests) as dead-*module* candidates that complement knip's dead-*export* signal from the module-reachability angle knip misses (precedence: knip is authoritative for dead exports; depcruise reachability ADDS unreachable whole-modules). **Blast-radius (sharpens state/data-flow ownership + temporal coupling):** when the review zooms into a single target file/entity, `npx depcruise <root-scope> --config <config> --output-type text --focus '<module-path-regex>'` lists everything reaching or reached-by it — its scoped dependency neighborhood (read-only; `--reaches '<regex>'` gives the downstream-only cone). Both run from the repo ROOT (a scoped scan under-counts cross-boundary afferent, per the root-scan rule above). **No config? Still scan** — when the probe classifies dependency-cruiser `installed-unconfigured`, run `npx depcruise . --no-config --output-type json --metrics` (with the same build-output `--exclude` as above): the full graph, `circular` flags, and folder Ca/Ce/I need NO rule config (verified live); only forbidden-rule violations require one, so the "no violations is NOT meaningful" note applies a fortiori. **Direction judgments (stability.mjs — the scan CAPTURES Ca/Ce/I, this JUDGES them).** Immediately after writing the depcruise JSON, run `node "$RPIV_PLUGIN_ROOT/skills/architectural-review/_helpers/stability.mjs" --graph=<scratchpad>/depcruise.json --churn=<the metrics.mjs output file> --target=<target>` and ingest its blocks per the Ground Truth Fold below: `---sdp-violations---` (Stable Dependencies Principle: a folder edge whose target is markedly MORE unstable, delta >= 0.25 — the stable thing now moves when the volatile thing does), `---cycles---` (Tarjan SCC over the captured graph — cycle detection that does not depend on a `no-circular` rule existing), `---volatile-hubs---` (churn x afferent inbound — the "where will this hurt you" prioritization composite), `---folder-instability---` (context for the L lens dispatch), `---module-order---` (Kahn levels, entry points first — NOT a finding: hold it for Step 3, where it is the authoritative review direction replacing the old LLM topo-sort dispatch).
     - madge (fallback module graph for **L**, run ONLY when dependency-cruiser is `absent`): `npx madge --extensions ts,tsx,js,jsx,mjs,cjs --json <source-root>` (add `--ts-config <tsconfig>` when the repo uses path aliases; madge emits paths RELATIVE to the scanned directory — scan from the repo ROOT so paths join with `churn-hotspots` rows). Feed the JSON to the SAME `stability.mjs` run (graph flavor autodetected): folder instability, SDP violations, cycles, and volatile hubs all derive from the raw edge list, so the direction analysis no longer disappears on repos without dependency-cruiser — the repos that need it most.
     - Python root (the probe's Python rows, or an `also_root:` with `ecosystem=python`; sharpens **L**): dependency-cruiser and madge do not read Python, so two read-only helpers stand in, each printing one status line first (`ok` / `unavailable: <why>` / `broken: <why>`), never a silent empty result.
       - import-linter `configured`: `node "$RPIV_PLUGIN_ROOT/skills/architectural-review/_helpers/import-contracts.mjs" "<python root>"` runs the root's `.venv` `lint-imports --no-cache`. Its `---import-contracts---` rows (`<contract>	KEPT|BROKEN`) are the repo's declared boundaries: each BROKEN contract, with the import chains under `---broken-contracts---`, is L ground truth, folded exactly like a dependency-cruiser `forbidden` violation. `installed-unconfigured` → SUGGEST contracts (`[tool.importlinter]`), as for `depcruise --init`. `broken:` → name it in `## Tool Coverage` and route through the degradation checkpoint; never read it as no violations.
       - grimp `installed`: `node "$RPIV_PLUGIN_ROOT/skills/architectural-review/_helpers/python-graph.mjs" "<python root>" --out <scratchpad>/python-graph.json` writes the root's import graph as madge-shaped JSON of files (read-only: `python -I -B`, no grimp cache). Feed it to the SAME direction judgments: `node "$RPIV_PLUGIN_ROOT/skills/architectural-review/_helpers/stability.mjs" --graph=<scratchpad>/python-graph.json --churn=<the metrics.mjs output file> --target=<target>`, and to the likec4 conformance fold as its `--graph`. When the target spans a JS root and a Python root, run stability once per graph. grimp does not feed lane.
       - pyright (sharpens **A / Fe**; a Python-only target, where `semantic.mjs` reports `unavailable` for want of a tsconfig): `node "$RPIV_PLUGIN_ROOT/skills/architectural-review/_helpers/python-semantic.mjs" "<target>" > <scratchpad>/python-semantic.txt` starts `pyright-langserver` from the project's `.venv`, else from PATH (the binary Claude Code's pyright LSP plugin uses), and prints `dead-exports-semantic` and `feature-envy-semantic` in `semantic.mjs`'s shapes, with `---semantic-status---` `ran-partial: python via pyright` (it computes no write-sites, type-fragmentation or projection signal, so those stay unmeasured, never clean). Pass that file as `warrant.mjs --semantic=<scratchpad>/python-semantic.txt`. `unavailable:` (no langserver, too large) or `broken:` goes through the degradation checkpoint. A dead-export row is a candidate, never a finding by itself: a library's public API is often used only outside it, and names in `__all__` are already left out. Before reporting one, the agent may confirm it with Claude Code's `LSP` tool (`findReferences` at the symbol) when that tool serves Python.
     - knip (sharpens **A**): `npx knip --reporter json` — dead exports/files within the target.
     - jscpd (sharpens **D**; v5 = self-contained Rust binary, also `cpd`): run it TWICE, merge, then bucket — on TypeScript neither of cpd's readers is complete alone (the javascript reader finds the most; the typescript reader alone finds copies a comment split in two), and a raw clone count measures copying, not architecture. Run from the repo root. **Thresholds**: when the probe row is `configured` (`config=<file>`), pass `-c <file>` and NO `--min-tokens` — the repo's own thresholds, paths and ignores are ground truth (jscpd does not auto-load its config); otherwise pass `--min-tokens 50`. Always pass `--absolute` (a config's `paths` make names relative to each scan root, which no later step can resolve). (1) `jscpd <target> --absolute --reporters json --output <scratchpad>/jscpd-js --silent {thresholds} --format javascript --formats-exts "javascript:ts,tsx,mts,cts,jsx"`; (2) only when the target holds `.ts`/`.tsx` files, the same with `--output <scratchpad>/jscpd-ts --format "typescript,tsx"`; (2b) only when the target holds `.py` files, the same with `--output <scratchpad>/jscpd-py --format python` and no `--formats-exts` (jscpd's Python reader; its clones never overlap the JS ones); (3) `node "$RPIV_PLUGIN_ROOT/skills/_shared/jscpd-merge.mjs" <scratchpad>/jscpd-js/jscpd-report.json [<scratchpad>/jscpd-ts/jscpd-report.json] [<scratchpad>/jscpd-py/jscpd-report.json] > <scratchpad>/jscpd-merged.json` — never merge by hand; take `statistics.total.percentage` from the jscpd-js report; (4) `node "$RPIV_PLUGIN_ROOT/skills/architectural-review/_helpers/dup-families.mjs" --clones=<scratchpad>/jscpd-merged.json --root=<repo root>`. Its output is what the D lens consumes: `---dup-families---` (cross-file production copy families ranked by SPREAD — areas, then folders, files, copies; `---dup-areas---` names each family's areas) are the D seeds; `---dup-test-prod---` rows (test or test-support code re-implementing production code) go to the **T** lens; `---dup-same-file---` rows are G/Lc context, never D findings; header counts `test_test` / `import_only` are reported, never dispatched. **Exit codes**: a jscpd exit 1 WITH a report written is the repo's own `threshold` gate tripping, not a failure — read the report. No report, or exit 2 from `jscpd-merge` / `dup-families` (`BROKEN <path>`), means no usable clone list: name the step in `## Tool Coverage` and route through the degradation checkpoint — never treat it as zero clones. A failed second pass leaves the first pass's list standing; record `jscpd: partial (typescript pass {cause})`. A failed Python pass likewise leaves the other passes' list standing; record `jscpd: partial (python pass {cause})`. `import_check_unreadable` > 0 means some clones could not be checked for import-only (kept, not dropped) — note the count. All steps write ONLY to the scratchpad (read-only on source). When present, jscpd is the **authoritative D signal**; `metrics` `dup-candidates` drops to corroboration + structural-Type-2 supplement (see precedence).

     - stryker (sharpens **T**, mutation testing): Mutation score distinguishes genuine test coverage from test theater. Read the tool-probe `---report-status---` lines: `mutation: present|stale-json|html-only|absent`. If `absent`, `stale-json`, OR `html-only` AND the tool is `configured`, run a **Tier 2 checkpoint** via `question` — with the broken states carrying sharper remedies than the generic run-stryker offer below:
       - `html-only`: "Mutation report exists but is HTML-only (not machine-ingestable). Add \"json\" to stryker reporters and re-run, or extract from the html?" — offer **"Add json reporter + re-run (Recommended)"** / **"Extract from mutation.html"** / **"Skip"**. On **Extract**: the html embeds the report as a **JavaScript assignment (`app.report = {...}` with string-concat guards like `"<"+"label"`), NOT parseable JSON** — slice the assignment's object literal and evaluate it in an isolated `node -e` (never `JSON.parse` the raw text), write the result to the scratchpad as json, then parse with `mutation.mjs`'s expected shape in mind. Extraction is minutes vs a full re-run's ~20+.
       - `stale-json`: mutation.json EXISTS but predates the html report — an html-only reporter config left an old json in place, so the "present" file describes an EARLIER run (`mutation.mjs` detects this too and refuses to parse it, emitting `stale-json`). Same options as `html-only`; never parse the stale numbers as current.
       - `absent`: "Mutation report absent. Run StrykerJS on `{target}`? {N} source files, estimated {X} min. Mutation testing finds tests that execute code but don't verify behavior — definitive test theater detection. High coverage + low mutation score is the strongest T-lens signal."
       Options: **"Run mutation testing (Recommended)"** / **"Skip — use coverage only"** / **"I'll run StrykerJS manually"**. On **Run**: `npx stryker run --mutate "<target>/**/*.ts" --reporters json --concurrency 4`. On **Skip**: record "T lens running without mutation signal" in `## Tool Coverage`. On **Manual**: the review continues; parse the report when available.
       When a report EXISTS and is not stale: check freshness via `git diff --name-only HEAD -- <target>` — if no files under the target changed since the report's mtime, use it directly. If files changed, re-offer the checkpoint ("Files changed since last mutation run. Re-run?").

     - cosmic-ray (Python mutation testing, sharpens **T**; the probe's `cosmic-ray` row): `mutation.mjs` reads a Cosmic Ray session (`cosmic-ray.sqlite`, else `session.sqlite`, at the Python root) through the root's `.venv` `cosmic-ray dump` when no Stryker report exists, with the same head lines and rows plus `incompetent=N`.      - ts-morph (sharpens **S / Fe / A**; status `configured`): `node "$RPIV_PLUGIN_ROOT/skills/architectural-review/_helpers/semantic.mjs" "<target>"` — type-resolved supersets of three metrics signals the type system sees and regex cannot: `---write-sites-semantic---` (writers per table/RPC, resolving **imported/aliased** table names — not just same-file consts), `---feature-envy-semantic---` (per-symbol **behavioralRefs vs dataRefs** split; data-only leans are dropped at source), `---dead-exports-semantic---` (exports with **zero external `findReferences`** — emitted ONLY when knip is absent; knip is the primary, dynamic-pattern-aware A tool, so when it ran this block is `skipped` and the slow `findReferences` pass is avoided), and `---type-fragmentation-semantic---` (**C** — `kind=drift`: one name with structurally DIFFERENT shapes; `kind=same-shape`: the SAME shape under DIFFERENT names = a missing shared type — the structural seed no name-based search or external tool produces). `write-sites-semantic` / `feature-envy-semantic` **SUPERSEDE** the regex `---write-sites---` / `---feature-envy-candidates---` for S / Fe whenever present and the run is not `ran-partial` (then both are read); `dead-exports-semantic` supersedes `---export-usage---` for A only on the knip-absent fallback path; `type-fragmentation-semantic` SEEDS the C lens (complementary to its name-based search). A run whose `tsconfig_errors:`, `parse_errors:` or `targets_unmeasured:` header is above 0 is PARTIAL (`targets_unmeasured` = a target in a multi-target run whose files are outside the first target's tsconfig program) (signals from those files are incomplete): record those counts in `## Tool Coverage`. On `ran-partial` the warrant keeps the regex seeds alongside the semantic ones and never treats an empty semantic block as clean. A target with source files that the tsconfig program does not include (a solution-style tsconfig with `references`) answers `broken:` — rerun with the tsconfig that includes the target.

   **Deterministic Ground Truth Fold** (authoritative at the Slop Map level). When knip and depcruise ran successfully, promote their output into non-negotiable Slop Map entries BEFORE the lens wave. Per line above, every folded entry is ground truth its lens MUST NOT re-report — each entry below names only the judgment-level residue that lens still owns:
   - **Knip → dead-code (A) ground truth**: Every `knip` unused export + unused file whose path is under the target becomes an **A-finding with severity set by knip's own category** (`exports` = 🟡, `files` = 🔵, `dependencies` = 🔴), prefix `K-`. A lens residue: judgment-level dead abstractions knip can't see (exported but semantically dead, stale abstractions behind `export *`).
   - **depcruiser → boundary/cycle (L) ground truth**: Every `depcruise` circular dependency or forbidden-rule violation whose `from`/`to` paths intersect the target becomes an **L-finding**. Forbidden-rule violations with `severity: error` are 🔴; `severity: warn` are 🟡; prefix `DC-`.
